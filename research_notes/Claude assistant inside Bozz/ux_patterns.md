# UX patterns for in-app AI assistants that change the app itself (layout, settings, content)

Research date: 2026-10-15. Scope: interaction design of assistants that EDIT the user's workspace, not just answer. Target product: Bozz (Tauri desktop student dashboard: pages of widgets, themes, notes, tasks, habits). Citation style: fact followed by (Source link). Where a claim rests on a secondary source (blog, aggregator, AI-generated guide), that is flagged.

## Key question 1: How do the named products let a user request changes and review them (placement, propose vs apply, diff/undo, apply/keep/revert, streaming, multi-step)?

### Takeaway
By late 2026 the field has converged on a small set of building blocks: a chat that lives in a right-hand side panel (optionally popped out as a floating window), a user-selectable "propose first" vs "apply live" mode, a visible step/tool log while work happens, and a coarse-grained restore (checkpoint / version / one-shot Ctrl+Z of the whole assistant turn) rather than fine-grained diff review for non-code products. Code tools (Cursor, Replit, Lovable, v0) add per-file Keep/Undo and auto-checkpoints; document tools (Craft, Notion, Word Copilot) add "suggest vs execute" modes and Keep it / Regenerate / Discard.

### Cited Findings

**Notion (Notion Agent, 2026)**
- Chat entry point is a face icon in the bottom corner of Notion; under "Switch chat mode" the user chooses a right-side sidebar OR a floating window; an Agent icon also sits at the top of the Inbox panel; past chats are reachable by hovering "Notion AI" in the sidebar and clicking a clock icon ([Notion Help: Notion Agent](https://www.notion.com/help/notion-agent)).
- Results involving data appear as an interactive table inside the chat; calendar scheduling shows ranked time suggestions in a schedule grid; Gmail write actions (sending) ask the user to confirm first; Slack posts appear as coming from the user, since the Agent acts as them ([Notion Help: Notion Agent](https://www.notion.com/help/notion-agent)).
- Scoped permissions: the Agent has the same permissions the user has; it cannot change workspace settings, share pages, change page permissions, create/edit comments, or create reminders ([Notion Help: Notion Agent](https://www.notion.com/help/notion-agent)).
- Plan mode exists ("Review & approve plans before Notion AI runs"): when on, the Agent won't make edits while planning; the plan page includes a goal, the steps it will take, and a preview of what will change (e.g. which pages it will edit); the user can tell it what to change and it revises; enabled under Settings > Mode > Plan. Note: the help page exists at that URL but the fetch redirected to the generic Notion AI hub, so the detail here comes from the search snippet of that page, not a full read ([Notion Help: Review & approve plans](https://www.notion.com/en-gb/help/review-and-approve-plans-before-notion-ai-runs)).
- Suggested edits (Sept 2026): the agent can "propose edits instead of applying them at once"; the user approves or rejects each proposed change in order; agents leave activity logs admins can review; agents can run on a schedule (secondary source, Collab365, published 1 Sept 2026) ([Collab365](https://spaces.collab365.com/posts/notion-agents-can-now-work-inside-your-pages-and-w-8yi_cn)).
- An "Edits" toggle in the AI console can be unchecked to restrict the AI to read-only access, so it offers suggested text instead of writing over or inserting content (secondary source, Matthias Frank) ([matthiasfrank.de](https://matthiasfrank.de/en/notion-updates/control-notion-ai-edits/)).
- Older inline flow: select text > Ask AI > pick a fix; new text appears BELOW the original with "Replace selection", "Try again", "Discard" (secondary, Nerdschalk; may be an older UI) ([Nerdschalk](https://nerdschalk.com/how-to-use-notion-ai/)).

**Craft (Craft Assistant)**
- Two modes with a mode selector at the bottom of the Assistant panel: "Explore" (the Assistant reads the document and proposes changes; nothing is modified until the user reviews and approves) and "Execute" (applies changes directly; edits appear live as it works) ([Craft support: Editing with Craft Assistant](https://support.craft.do/en/ai-assistant/editing)).
- Execute mode can change text blocks, styling (highlights, colours, backgrounds, dividers), create subpages, create/duplicate documents, create folders, move documents, reorganise sections, and delete blocks/documents/folders ([Craft support](https://support.craft.do/en/ai-assistant/editing)).
- Undo: Ctrl+Z / Cmd+Z reverts the Assistant's ENTIRE last response as one step; repeat to undo several; users can also ask the Assistant to revert or adjust ([Craft support](https://support.craft.do/en/ai-assistant/editing)).
- Editing only available on Max/Fast models; Core and On-device are read-only; Execute mode on macOS and iOS only (not Windows/Web yet) ([Craft support](https://support.craft.do/en/ai-assistant/editing)).
- Craft Agents is a separate terminal/MCP product using Claude that can add documents, update blocks, manage collections ([agents.craft.do](https://agents.craft.do/docs)).

**Raycast AI (AI Extensions)**
- AI Extensions are @-mentioned from Quick AI, AI Chat, or Root Search; typing "@" lists installed extensions; several can be chained in one prompt; "the AI shows you the call as it happens" ([Raycast manual: AI Extensions](https://manual.raycast.com/ai/ai-extensions)).
- Approval card: when a tool needs approval the chat pauses and shows a card describing the action; the manual warns "The description is AI-generated, so check it before you allow"; for shell commands "Show Command" reveals the exact command; buttons: Allow (Enter, run once), Always allow (Cmd+Enter, skip future approval), Deny (Esc); with multiple pending calls the Action Panel adds Allow All / Deny All ([Raycast manual](https://manual.raycast.com/ai/ai-extensions)).
- Permission modes in Settings > AI > Tools: "Ask" (prompts for anything not read-only), "Auto" (default on paid plans: runs safe/read-only tools and edits in the working directory, always asks before reading credentials like .env or before destructive actions), "Always Allow"; per-chat overrides via "Change Permissions..."; "Auto-review Rules" pair an action with Allow automatically / Ask first; "Globally Allowed Tools" list with See Allow List / Reset All ([Raycast manual](https://manual.raycast.com/ai/ai-extensions)).
- MacStories' launch hands-on: invoke by typing @ then continue in natural language or pick a suggested prompt; about 50 existing extensions were AI-enabled at launch ([MacStories](https://www.macstories.net/reviews/hands-on-with-raycasts-new-ai-extensions/)).

**Microsoft Copilot: Windows Settings agent and Word**
- Windows 11 "agent in Settings" (announced 6 May 2025 for Copilot+ PCs): user describes a problem in natural language in the Settings search box (e.g. "my mouse pointer is too small"); the agent recommends steps and "With your permission and at your initiation, it can even complete the actions to change your settings on your behalf"; on-device model; English first; Snapdragon first, AMD/Intel later ([BleepingComputer, 2025-05-06](https://www.bleepingcomputer.com/news/microsoft/microsoft-unveils-new-ai-agents-that-can-modify-windows-settings/)).
- It is woven into the Settings search box, not a separate chatbot ([allthings.how](https://allthings.how/?p=7455); secondary).
- Windows Insider Build 26120.6780 (Beta): Settings home shows recently modified settings under "Recommended settings" with an inline agent action for each; the search flyout shows adjustable results; if a setting can't be adjusted further a dialog explains why and offers a control (example: searching "increase volume" at max volume opens a dialog with a slider). The post does NOT mention confirmation or undo ([Windows Insider Blog](https://blogs.windows.com/windows-insider/?p=178299)).
- Critique: BetaNews warned a user could accidentally make a change they cannot work out how to undo, and asked whether it is a new attack vector ([BetaNews, 2025-05-07](https://betanews.com/2025/05/07/microsoft-now-has-ai-agents-that-can-change-windows-11-settings-should-we-be-delighted-or-terrified/)).
- Word "Draft with Copilot": after generation the user picks "Keep it", "Regenerate", "Discard it", or refines via the compose box (e.g. "Make it sound professional") ([Microsoft Support](https://support.microsoft.com/en-us/office/start-a-draft-with-copilot-in-word-069c91f0-9e42-4c9a-bbce-fddf5d581541)). "Keep it" converts the draft to normal document content and the Copilot draft window disappears; "Regenerate" keeps earlier drafts so you can page back ("draft 2 of 3") ([Northwestern IT KB](https://services.northwestern.edu/TDClient/30/Portal/KB/Article/2605/Microsoft-365-M365-Copilot-within-Word)).

**Perplexity Comet (browser agent)**

**Claude Artifacts**

**v0 (Vercel)**
- "Ship features, refine designs, update copy, and create live prototypes, all with a prompt"; "Real-time preview of your app, with visual progress indicators and rich UI feedback for all agent actions"; auto-fixes errors ([v0 docs](https://v0.app/docs)). **Lovable**
- Preview toolbar modes: "Select elements (S)" (click one or more elements; they attach to the chat input as references and the prompt applies to all); "Edit text inline (T)" (edit text in place then click "Send" to apply; first 100 edits per account free); "Draw annotation (D)" (sketch sent as an image with the message); "Add comment (C)"; toolbar can be docked/minimised/hidden; requests can be queued while Lovable works ([Lovable docs: Visual edits](https://docs.lovable.dev/features/visual-edit)).
- Versioning: every change creates a version automatically, no save button; History panel from the top bar or the menu next to the message input, with History and Bookmarks tabs; reverting restores code only (not the database); chat history is preserved and later edits stay in chat so they can be reapplied; "Edit message" then "Revert and resend" to branch ([Lovable docs: History](https://docs.lovable.dev/features/projects/history)).
- A revert option sits under each AI response; restoring creates a new edit card (like a git revert commit) so history is preserved ([Lovable blog](https://lovable.dev/blog/versioning-with-lovable-two-point-zero); [Lovable FAQ](https://lovable.dev/faq/ai-agent/issues)).

**Replit Agent**
- Chat lives in the Project Editor ("just start chatting"); Plan mode creates an ordered task list the user reviews and refines, with "Accept tasks" and "Revise plan" options; Agent creates checkpoints as it works "so you can roll back to any previous state"; background work tracked through a Kanban-style Task system ([Replit docs](https://docs.replit.com/replitai/agent)).

**Cursor (Agent / Composer)**
- Agent lives in a sidepane opened with Cmd+I; side chats via /side or /btw; the Edit files tool will "Suggest edits to files and apply them automatically"; checkpoints are created automatically before significant changes; clicking a checkpoint in the chat timeline previews files at that point, restoring reverts files but leaves the conversation intact; also a "Restore Checkpoint" button on earlier requests; checkpoints stored locally, separate from Git; queued messages can be reordered; "Send now" steers the active turn at the next tool call ([Cursor docs: Agent overview](https://cursor.com/docs/agent/overview)).
- Per-file Keep/Undo plus "Keep All" / "Undo All" in a Review panel; check/X icons appear on hover of a file row in Pending mode; Keep All / Undo All are hidden by design when only one file changed; a moderator notes Undo/Keep moved into the breadcrumbs "and are easy to miss" ([Cursor forum](https://forum.cursor.com/t/per-change-keep-undo-buttons-missing-after-agent-edits-only-undo-all-available/158983); [Cursor forum](https://forum.cursor.com/t/cursor-undo-all-and-keep-all-buttons-disappeared/152781)).
- Pain points: the Review panel tracks all session edits, not pending diffs, so it stays populated after accept/reject; pending review disappears after restart "as if I had clicked Keep"; users complain Cursor "keeps auto-accepting its own changes"; users dislike the new diff view ([Cursor forum](https://forum.cursor.com/t/review-panel-doesnt-dismiss-rendering-it-useless-reproduced-by-another-user-too/163722); [Cursor forum](https://forum.cursor.com/t/review-of-changes-done-in-agent-chat-window-disappears-after-cursor-restart/163021); [Cursor forum](https://forum.cursor.com/t/cursor-keeps-auto-accepting-its-own-changes/152233); [Cursor forum](https://forum.cursor.com/t/i-dont-like-the-new-cursor-diff-view/145154)).

### Inferences
- The dominant placement for a workspace-editing assistant is a right side panel with an option to detach as a floating window (Notion), or a side pane toggled by shortcut (Cursor Cmd+I). Full-screen chat is avoided because the user needs to see the thing being changed.
- "Mode" toggles (Craft Explore/Execute, Notion Plan mode + Edits toggle, Raycast Ask/Auto/Always Allow, Replit Plan mode) are the standard way to let the user choose between propose-first and apply-live. Defaults differ: Raycast defaults to Auto on paid plans; Craft and Notion default to applying.
- For non-code artefacts the undo granularity is "one assistant turn = one undo step" (Craft) or "restore checkpoint/version" (Cursor, Replit, Lovable). Fine-grained per-change accept/reject appears only where there is a natural diff (code, text suggestions, Notion suggested edits).
- Selection-as-scope is a recurring trust device: Figma "select layers first", Lovable "Select elements", Claude "Edit with Claude" on highlighted text. For Bozz, letting the user click a widget/page before asking is likely more reliable than describing it in words.
- Cursor's forum shows that hiding Keep/Undo controls (breadcrumbs, hover-only icons, hidden when one file changed) is a repeat complaint; controls for reverting AI edits should be persistent and obvious.

## Key question 2: What builds or breaks trust in agentic edits of user data in consumer apps?

### Takeaway
Trust-building devices documented across products: a pre-execution plan/preview (Notion Plan mode, Replit Plan mode, Shape of AI "Action plan" and "Sample response"), a visible live log of actions (Raycast "shows you the call", Comet step log, Shape of AI "Stream of Thought"/"Shared vision"), explicit scoped permissions (Notion's "same permissions as you, cannot change workspace settings"), approval cards with Allow/Always allow/Deny, and reliable coarse undo (Craft Ctrl+Z whole turn, Cursor checkpoints). Trust-breakers documented: silent default changes (VS Code Copilot co-author trailer), unrecoverable settings changes (BetaNews on Windows agent), edits that destroy formatting (Notion AI translation reviews), AI deleting pages with failing revert (Reddit via aggregator), and review controls that vanish or auto-accept (Cursor).

### Cited Findings
- Google PAIR: "when users have the right level of control over the system, they're more likely to trust it"; core considerations are aligning feedback with model improvement, communicating the value of feedback, and balancing control with automation; "Always provide a way to see, and ideally edit, data collected" ([PAIR Guidebook: Feedback + Control](https://pair.withgoogle.com/chapter/feedback-controls/)).
- PAIR Errors chapter: "Creating paths for users to take action in response to the errors they encounter encourages patience with the system"; errors can "support faster learning by experimentation, help establish correct mental models"; the worksheet separates system-limitation errors from context errors (system works but the user perceives an error) ([PAIR: Errors + Graceful Failure](https://pair.withgoogle.com/chapter/errors-failing/); [worksheet PDF](https://pair.withgoogle.com/worksheet/errors-failure.pdf)).
- Microsoft HAX Pattern 9C "Undo automated actions": problem is "The AI system incorrectly altered user input"; solution "revert to a previous state or undo the AI system's actions"; listed pitfall: repeated corrections become burdensome. Pattern 9E "Batch-editing data": let users correct "a batch of related data from a single interaction" ([HAX Design Library](https://www.microsoft.com/en-us/haxtoolkit/product-category/chatbot/page/5)).
- The 18 HAX guidelines relevant here: G7 Support efficient invocation, G8 Support efficient dismissal, G9 Support efficient correction, G10 Scope services when in doubt, G11 Make clear why the system did what it did, G16 Convey the consequences of user actions, G17 Provide global controls, G18 Notify users about changes ([HAX Design Library](https://www.microsoft.com/en-us/haxtoolkit/library/example,guideline,pattern/3,6,20/); [Amershi et al., CHI 2019](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/)).
- Shape of AI "Governors" patterns: Action plan (show steps before executing), Branches (keep the path back to the original), Controls (pause mid-stream to adjust), Draft mode (low-cost exploration until final), Sample response (confirm intent for complex prompts), Shared vision (live visibility into AI actions on a shared canvas), Stream of Thought (expose reasoning/tool use for auditing), Variations (compare results), Verification (confirm decisions before proceeding); "Trust builders": Footprints (trace the AI's steps from prompt to result), Disclosure, Caveat ([shapeof.ai](https://www.shapeof.ai/)). Note: shapeof.ai has no explicit "Undo" or "Confirmation" pattern name; Verification and Branches cover it.
- Raycast's approval card warns the user that the action description is AI-generated and should be checked before allowing; "Auto" mode always asks before reading credentials or destructive actions ([Raycast manual](https://manual.raycast.com/ai/ai-extensions)).
- Notion Agent summary-of-work patterns: interactive tables in chat for data results, confirm-before-send for Gmail, activity logs for admins ([Notion Help](https://www.notion.com/help/notion-agent); [Collab365](https://spaces.collab365.com/posts/notion-agents-can-now-work-inside-your-pages-and-w-8yi_cn)).
- Trust breaker: VS Code (spring 2026) switched the git co-author trailer default from off to "all", tagging every AI-involved change with no release notes and no user alert, even when chat.disableAIFeatures was true; the approving reviewer apologised on Hacker News for "turning this feature on by default without sufficient upfront validation"; default reverted in 1.119 ([Windows Central](https://windowscentral.com/software-apps/this-could-cost-people-their-jobs-vs-code-added-copilot-as-co-author-without-permission-or-notice); [WebProNews](https://www.webpronews.com/vs-codes-sneaky-copilot-co-authorship-how-microsoft-rewrote-git-histories-and-lost-developer-trust/)).
- Trust breaker: a Reddit complaint (via aggregator, original thread not opened) that Notion AI repeatedly deletes pages and moves content to trash during page operations, with a commenter noting revert sometimes fails ([reddit.sentinel-team.org analysis](https://reddit.sentinel-team.org/analyses/172764); secondary, unverified).
- Trust breaker: an AWS Marketplace review says Notion AI "sometimes suffers bugs preserving text format while translating or editing, which forces users to redo the page" ([AWS Marketplace reviews](https://aws.amazon.com/marketplace/reviews/reviews-list/prodview-eoc4gcvwcs3a6?page=759)).
- Trust breaker: Reddit-sourced blogs list Notion AI output that "sounds like a robot wrote it, completely stripping away your unique voice" and incorrect/nonsensical content ([eesel.ai](https://www.eesel.ai/blog/notion-ai-improve-or-rewrite-content); [ones.com](https://ones.com/blog/?p=11477); secondary).
- Trust breaker: BetaNews on the Windows Settings agent: a user "could accidentally make a change that they cannot work out how to undo" ([BetaNews](https://betanews.com/2025/05/07/microsoft-now-has-ai-agents-that-can-change-windows-11-settings-should-we-be-delighted-or-terrified/)).
- Trust breaker: Cursor users report the agent auto-accepting its own changes in some workspaces, Keep/Undo buttons disappearing, and pending review lost on restart ([Cursor forum](https://forum.cursor.com/t/cursor-keeps-auto-accepting-its-own-changes/152233); [Cursor forum](https://forum.cursor.com/t/keep-all-undo-buttons-dissapear/147551)).
- GenUI critique: "one of the biggest challenges of many GenUI interfaces is the inability to move backward"; even when Undo exists users may not use it "if it's not visible or intuitive"; suggested fixes include editing earlier prompts and a history with named checkpoints ([UX Planet: GenUI foundational patterns](https://uxplanet.org/genui-design-foundational-patterns-633320d0dfea); secondary).
- A design spec for an AI-assisted workspace states AI suggestions should carry recommendation, reason, confidence, preview, apply, and dismiss, and that "AI changes are never silent" ([ontocode UX_PATTERNS](https://ontocode-vs.readthedocs.io/en/latest/ui/UX_PATTERNS/); minor project, illustrative only).
- A workflow-builder changelog: Ctrl+Z reverts to the previous AI-generated version in the same session, framed as "reducing the risk of losing a working state while iterating with AI" ([AesthetixCRM changelog](https://ideas.aesthetixcrm.com/en/changelogs/69fdf29879ee7c0b0fd84794/undo-redo-support-for-ai-builder-in-workflows); minor product).
- Craft: Ctrl+Z reverts the whole assistant response as one step; users can also ask the assistant to revert ([Craft support](https://support.craft.do/en/ai-assistant/editing)).
- Lovable: reverting restores code but NOT database data, an explicit scoping of what undo covers ([Lovable docs](https://docs.lovable.dev/features/projects/history)).

### Inferences
- The most-cited trust mechanisms map cleanly onto Bozz features: (1) a plan/preview card before multi-step changes ("I'll create page X with widgets A, B, C and set theme Y"), (2) a live action log while applying, (3) a post-hoc "I changed X, Y, Z" summary with a single "Undo all" that reverts the turn atomically (Craft model), (4) hard limits on what the assistant may touch (Notion model: cannot change account/sync settings, cannot delete without confirmation).
- "Never silent" is the thread through every complaint: unannounced default changes, lost formatting, pages trashed. A Bozz assistant should produce a visible change receipt even for one-line edits like "make the text bigger".
- Undo must be as reliable as the app's own store. Bozz has a history of torn-store and sync-clobber incidents (see memory), so the assistant should snapshot the store before any multi-widget change and expose "Restore snapshot" the way Cursor/Replit expose checkpoints.

### Gaps
- No controlled UX study (NN/G or academic) comparing propose-first vs apply-live for consumer workspace edits was found; evidence is product practice and anecdote.
- The Reddit "Notion AI deletes pages" claim could not be verified at source.

## Key question 3: What does Apple's App Intents / Siri design say about exposing an app's actions to an assistant (verbs, parameters, confirmation)?

### Takeaway
Apple's model is action = intent with typed `@Parameter`s and a parameter summary, system-driven disambiguation dialogs, an explicit `requestConfirmation` step (plain, with custom dialog/action names, or with a snippet view), and a result that reports success/failure. Apple has not published first-class guidance on risk levels, step-up auth or audit trails for agentic Siri actions (a developer forum question on exactly this went unanswered).

### Cited Findings
- An intent that needs data declares it as parameters: "An app intent parameter is a property that you annotate with the `@Parameter` macro. To improve the experience of specifying parameter values, include parameter summaries" ([Apple: App Intents](https://developer.apple.com/documentation/appintents/app-intents.md)).
- `IntentDialog` holds "the text you want the system to display, or speak, when requesting a value, asking for disambiguation, or confirming an action"; an intent "returns a result to tell the system when it completes its action, and whether the action was successful or failed" ([Apple: App Intents](https://developer.apple.com/documentation/appintents/app-intents.md)).
- `requestConfirmation` exists in several forms: basic (displays a prompt asking for confirmation before performing the intent), with custom dialog and action names, and with an interactive snippet in the prompt ([Apple: AppIntent](https://developer.apple.com/documentation/appintents/appintent.md)).
- Legacy SiriKit framed confirmation as a phase "after you resolve the parameters of an intent, but before you handle that intent", for final validation and checking services are available ([Apple: Confirming the details of an intent (SiriKit)](https://developer.apple.com/documentation/sirikit/confirming-the-details-of-an-intent.md)).
- Apple's App Intents overview notes that Siri's personal context, onscreen awareness and in-app actions are "in development and will be available with a future software update" ([Apple: App Intents](https://developer.apple.com/documentation/appintents/app-intents.md)).
- Design guidance is pointed to the HIG pages for App Shortcuts, Siri, and Action Button ([Apple: App Intents](https://developer.apple.com/documentation/appintents/app-intents.md)).
- Unanswered developer forum thread "Confirmation, permissions, and reversibility for agentic actions" asked: is there a first-class confirmation API requiring explicit approval; can an intent declare a risk/sensitivity level; what auth context (biometric, user presence) is available to a Siri-invoked intent; is there an audit trail; how are partial failures in multi-step flows handled. The only reply (Apple DTS) redirected the poster to the main forums ([Apple Developer Forums thread 833656](https://developer.apple.com/forums/thread/833656)).
- HIG generative AI guidance (as relayed by an Apple-affiliated forum responder): "Letting people know when and where your app uses AI sets expectations and gives people the opportunity to knowingly choose to use an AI-powered feature"; the Machine Learning HIG covers "communicating the limitations" ([Apple Developer Forums thread 799064](https://developer.apple.com/forums/thread/799064)). WWDC25 session 248 lists "Human Interface Guidelines: Generative AI" and "Machine Learning" as separate resources ([WWDC25 session 248](https://developer.apple.com/videos/play/wwdc2025/248)).
- Third-party paraphrase of the HIG ML/GenAI pages: features should enhance without surprising people, AI content clearly attributed, users get controls to edit, regenerate, or dismiss output and to correct mistakes (not Apple's wording) ([raintree-technology apple-hig-skills](https://awesome.ecosyste.ms/projects/github.com%2Fraintree-technology%2Fapple-hig-skills)).

### Inferences
- The App Intents shape (verb-named intent, typed parameters with summaries, system-handled disambiguation, opt-in confirmation with a preview snippet, structured result) is a good template for Bozz's tool schema: e.g. `CreatePage(title, widgets[])`, `AddWidget(page, type, size)`, `SetTheme(name)`, `SetTextScale(level)`, each with a "needs confirmation" flag and a snippet preview.
- Apple leaves risk-tiering and audit to the app; Bozz would need to define its own tiers (read-only / reversible edit / destructive) and its own change log.

### Gaps
- The HIG "Generative AI" page body was not retrievable; exact Apple wording on review/undo not captured.
- No Apple answer on risk levels or audit trails for agentic Siri actions exists in the sources found.

## Key question 4: Command palettes with natural language (Raycast, Linear, Superhuman): how do they blend typed commands and free text?

### Takeaway
The documented blend is: a classic fuzzy-matched action list (Cmd+K) that also teaches shortcuts, plus an "@" (Raycast) or sidebar-prompt (Superhuman Go) escape hatch into free-text AI. Raycast is the clearest example of one input box serving both: typed root search, @-mentioned extensions, and natural-language continuation in the same field. Windows Settings does the same inside its search box.

### Cited Findings
- Superhuman Command (Cmd+K): "you can instantly do any action, and also learn the shortcut for next time"; a command palette is "a free-form input field that helps users find an action by narrowing down a list, based on what they type" ([Superhuman blog](https://blog.superhuman.com/how-to-build-a-remarkable-command-palette/)).
- Superhuman Go (after the Grammarly rebrand) uses "a familiar sidebar interface where users can view suggestions, enter prompts, or interact with various AI agents" ([max-productive.ai](https://max-productive.ai/ai-tools/superhuman/); secondary).
- Raycast: @ in Root Search, Quick AI or AI Chat lists AI Extensions; the user then continues typing the command in natural language or picks a suggested prompt; multiple extensions can be chained in one message ([Raycast manual](https://manual.raycast.com/ai/ai-extensions); [MacStories](https://www.macstories.net/reviews/hands-on-with-raycasts-new-ai-extensions/)).
- Windows Settings: natural-language requests go into the existing Settings search box, and search results become actionable items (inline agent action) rather than a separate chat ([Windows Insider Blog](https://blogs.windows.com/windows-insider/?p=178299); [allthings.how](https://allthings.how/?p=7455)).
- Arc Max attaches AI to existing gestures (Cmd+F hold, Shift+hover) instead of a palette ([Arc](https://arc.net/max)).
- Shape of AI "Wayfinders" patterns for the blank-box problem: Suggestions (example prompts), Nudges, Templates, Follow up (ask for more info when unclear), Initial CTA ([shapeof.ai](https://www.shapeof.ai/)).
- Wattenberger's critique (via Simon Willison): chat opens as a blank page that doesn't signal what the tool is for; "Good tools make it clear how they should be used" and how they should not ([Simon Willison](https://simonwillison.net/2023/May/15/why-chatbots-are-not-the-future)).

### Inferences
- For Bozz, which already has Ctrl+Q quick capture, a single palette where typed text first fuzzy-matches known actions ("Change theme", "Add widget") and falls through to the assistant for anything unmatched (with the matched action list shown as suggestions) mirrors Raycast/Windows Settings and avoids a blank chat box.
- Showing the equivalent "manual" action next to an AI-applied change (Superhuman's "learn the shortcut") doubles as explanation (HAX G11) and teaches the UI.

### Gaps
- No primary source on Linear's natural-language or AI command menu (docs 404).
- No primary Superhuman Go documentation reached; only a secondary review.

## Key question 5: Published UX research / guidelines on AI that edits the user's workspace (NN/G, HAX, PAIR, Apple HIG, Shape of AI, Litt, Wattenberger)

### Takeaway
There is no single guideline set specifically for "AI that edits your workspace"; the applicable material is HAX G7-G11/G16-G18 and Pattern 9C/9E (undo, batch correction), PAIR's Feedback + Control and Errors chapters, Shape of AI's Governors/Trust-builders catalogue, Apple's disclosure/limitations HIG notes, and essayists (Litt: malleable software via LLMs; Wattenberger: chat is a poor primary interface). No NN/G article specifically on agentic editing was found; NN/G's relevant principle is the long-standing "User control and freedom / support undo and redo" heuristic.

### Cited Findings
- Amershi et al., "Guidelines for Human-AI Interaction" (CHI 2019): 18 guidelines validated with 49 practitioners against 20 products ([Microsoft Research](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/)); full list in Key question 2 ([HAX Design Library](https://www.microsoft.com/en-us/haxtoolkit/library/example,guideline,pattern/3,6,20/)).
- HAX Pattern 9C (undo automated actions) and 9E (batch-edit data) ([HAX](https://www.microsoft.com/en-us/haxtoolkit/product-category/chatbot/page/5)).
- PAIR Guidebook (published 2019-05-08, updated 2021-05-18; a later edition reorganised into design patterns plus six chapters): Feedback + Control and Errors + Graceful Failure chapters as cited above ([PAIR Feedback + Control](https://pair.withgoogle.com/chapter/feedback-controls/); [PAIR Errors](https://pair.withgoogle.com/chapter/errors-failing/); [PAIR guidebook](https://pair.withgoogle.com/guidebook)).
- Shape of AI pattern catalogue: six groups (Wayfinders, Inputs, Tuners, Governors, Trust builders, Identifiers); "Inline Action" lets users ask AI about content already on the page ([shapeof.ai](https://www.shapeof.ai/)). ElPassion cites Microsoft 365 Copilot inline editing as the example of Inline Action, noting "the design work is choosing verbs" ([ElPassion](https://www.elpassion.com/blog/generative-ui-patterns); secondary).
- Apple HIG: separate "Generative AI" and "Machine learning" pages; disclosure and limitation communication emphasised ([Apple forums 799064](https://developer.apple.com/forums/thread/799064); [WWDC25 248](https://developer.apple.com/videos/play/wwdc2025/248)).
- Geoffrey Litt, "Malleable software in the age of LLMs" (2023): LLMs are "a step change in tool support for end-user programming"; the obstacle had been turning fuzzy intent into formal executable code; predicted shifts include users extending existing apps and single-purpose GUIs built for one task ([Litt, Buttondown](https://buttondown.com/geoffreylitt/archive/malleable-software-in-the-age-of-llms/); [geoffreylitt.com](https://www.geoffreylitt.com/2023/03/25/llm-end-user-programming)). Litt now works at Notion on malleable software ([bmannconsulting notes](https://bmannconsulting.com/notes/geoffrey-litt/); secondary). Follow-up: "Codifying a ChatGPT workflow into a malleable GUI" ([Litt](https://buttondown.com/geoffreylitt/archive/codifying-a-chatgpt-workflow-into-a-malleable-gui/)).
- Amelia Wattenberger, "Why chatbots are not the future" (2023), as summarised by Simon Willison: chat is "a terrible interface for LLMs"; "Good tools make it clear how they should be used"; problems listed by a digest: blank page, forced typing, control inversely related to automation ([Simon Willison](https://simonwillison.net/2023/May/15/why-chatbots-are-not-the-future); [acacess digest](https://acacess.substack.com/p/daily-productive-sharing-725)).
- "The undo problem in AI products" (uxdesign.cc) exists but returned HTTP 403; it reportedly references NN/G heuristic #3 "User control and freedom / Support Undo and Redo" ([uxdesign.cc](https://uxdesign.cc/the-undo-problem-in-ai-products-c90ff080de3b); not read in full).
- A 2026 ParallelHQ piece on LLM chat UX patterns and an ElPassion piece on generative UI patterns (16 Aug 2026) exist as secondary 2026 surveys ([ParallelHQ](https://www.parallelhq.com/blog/llm-chat-ux-patterns); [ElPassion](https://www.elpassion.com/blog/generative-ui-patterns)).

### Inferences
- A compact Bozz design brief derivable from the guidelines: G1/G2 (tell the user what the assistant can change: pages, widgets, theme, text size; and what it can't: sync, account), G7 (one shortcut to invoke), G8 (Esc dismisses without side effects), G9 (one-click undo of the whole turn + per-item revert in the receipt), G10 (if ambiguous, ask or show a preview instead of guessing: "Which page?"), G11 (receipt says what and why), G16 (warn before deletion), G17 (global toggle: propose-first vs apply-live), G18 (notify when it changed something not on screen).
- Litt's framing supports Bozz's "make me a widget that..." ambition: the assistant as a malleability layer, generating single-purpose widgets from intent, with the GUI result editable afterwards (Lovable/Claude "edit directly" pattern).

### Gaps
- No NN/G article specifically on agentic/generative editing surfaced; the undo heuristic is the only NN/G anchor and was not read at source.
- uxdesign.cc "undo problem" article not readable (403).
- No 2025-2026 peer-reviewed study on preview-vs-apply for consumer workspace agents found.
